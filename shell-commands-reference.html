06 Permissions & Ownership
Permission notation: rwxr-xr-x = owner: read+write+execute, group: read+execute, others: read+execute. Octal: r=4, w=2, x=1. So 755 = 7(rwx) 5(r-x) 5(r-x).

📁  File System & Navigation

Use find with combined predicates. The key flags are -size for file size and -mtime for modification time.

find / -type f -name "*.log" -size +100M -mtime -7 2>/dev/null
  • -size +100M — greater than 100 megabytes
  • -mtime -7 — modified less than 7 days ago (minus = within last N days)
  • 2>/dev/null — suppress "Permission denied" errors on system dirs

To also display human-readable sizes of matched files:

find /var/log -type f -name "*.log" -size +100M -mtime -7 -exec ls -lh {} \;

Hard link: Another directory entry pointing to the same inode (data blocks). Data persists until all hard links are removed.

  • Cannot cross filesystem boundaries
  • Cannot link to directories (normally)
  • Remains valid if the original filename is removed — both point to the same data

Soft (symbolic) link: A special file containing a path reference to another file/directory.

  • Can cross filesystems and link to directories
  • Becomes a "dangling symlink" (broken) if the target is removed
  • Can be identified by ls -la showing lrwxrwxrwx and the -> arrow
ln target.txt hardlink.txt # hard link (same inode) ln -s /etc/nginx/nginx.conf ./nginx.conf # soft link (path reference) ls -li hardlink.txt target.txt # same inode number confirms hard link

Use hard links for backup deduplication. Use soft links for cross-directory shortcuts, version switching (e.g., python → python3.11), and config management.

Step 1 — Stop all writes immediately. Every new write potentially overwrites deleted data. Unmount the filesystem if possible, or stop applications writing to it.

Step 2 — Check if any process still holds a file descriptor open:

lsof | grep deleted # list processes with open-but-deleted file handles

If found, you can recover the data via /proc without restarting:

cp /proc/<PID>/fd/<FD_NUM> /tmp/recovered_file

Step 3 — Use filesystem recovery tools:

  • extundelete for ext3/ext4: extundelete /dev/sda1 --restore-all
  • testdisk / photorec — cross-filesystem partition and file recovery
  • foremost — carve files by header signatures

Prevention: Use LVM/ZFS/BTRFS snapshots before bulk deletes. Consider trash-cli instead of bare rm, or alias rm to rm -i.

Use rsync with the -a (archive) flag — it combines recursive, preserve-permissions, preserve-timestamps, preserve-symlinks, and group/owner.

rsync -avzP /local/dir/ user@remote:/remote/dir/
  • -a — archive: equivalent to -rlptgoD
  • -v — verbose output
  • -z — compress during transfer
  • -P — progress display + resume partial transfers

The trailing slash on source (/local/dir/) copies the contents, not the directory itself. Always do a dry run first:

rsync -avzn /local/dir/ user@remote:/remote/dir/ # -n = dry run, no changes made

Alternative using tar over SSH (single command, no rsync needed on remote):

tar czf - /local/dir | ssh user@remote "tar xzf - -C /remote/"

Use find with -type d -empty. Always list first, then delete:

find /path -type d -empty # preview: list empty dirs find /path -type d -empty -delete # delete them

The -delete flag processes deepest paths first (depth-first), so a single run correctly removes nested empty directories (e.g., a/b/c where each level is empty).

To exclude the root path itself from deletion:

find /path -mindepth 1 -type d -empty -delete
📝  Text Processing

Combine awk (field extraction), sort, uniq -c (count), and head:

awk -F',' 'NR>1 {print $3}' data.csv | sort | uniq -c | sort -rn | head -10
  • -F',' — comma as field delimiter
  • NR>1 — skip the header row
  • sort | uniq -c — count occurrences (uniq requires sorted input)
  • sort -rn — sort by count numerically, descending

For CSV with quoted fields containing commas (e.g., "Smith, John"), use Python's csv module — awk will split those incorrectly.

Option 1 — find + sed (portable):

find /etc/myapp -name "*.conf" -exec sed -i 's/prod-server/staging-server/g' {} \;

Option 2 — grep + xargs (faster for many files):

grep -rl "prod-server" /etc/myapp/ | xargs sed -i 's/prod-server/staging-server/g'

sed -i.bak 's/prod-server/staging-server/g' file.conf # creates file.conf.bak

On macOS, sed -i requires an explicit extension argument: sed -i '' 's/...' file

Use comm (requires sorted input) or grep -F -x -v:

comm approach (most efficient):

comm -23 <(sort file1.txt) <(sort file2.txt)

comm outputs 3 columns: lines only in file1, only in file2, in both. Flag -23 suppresses columns 2 and 3 — leaving only lines unique to file1.

grep approach (works on unsorted input, slower on large files):

grep -F -x -v -f file2.txt file1.txt
  • -F — fixed string, not regex
  • -x — match whole line
  • -v — invert: lines NOT matching
  • -f file2.txt — use file2 lines as the pattern list

Use sed with -n and a print range — it stops reading after line 600:

sed -n '500,600p' largefile.log

Or with awk (also quits early with exit):

awk 'NR>=500 { print } NR==600 { exit }' largefile.log

Or the classic head | tail pipeline:

head -600 largefile.log | tail -101

Avoid loading the whole file into memory. sed -n 'N,Mp' and the awk-with-exit approach are the most efficient — they stop reading once the range is found.

⚙️  Process Management

Why: On Linux, deleting a file removes the directory entry but the inode and data blocks are only freed when all file descriptors pointing to that inode are closed. The writing process still holds an open fd, so the kernel keeps the data.

Confirm the problem:

lsof | grep deleted # shows processes holding open-but-deleted files df -h # disk still shows as full

Recover space without restart — truncate via /proc:

ls -la /proc/<PID>/fd/ # find the fd number for the deleted file > /proc/<PID>/fd/<FD_NUM> # truncate to 0 bytes — frees space immediately

The process continues writing to the same fd. The disk space is freed instantly and no restart is needed.

Prevent this long-term: Configure logrotate with the copytruncate directive, or have your application respond to SIGHUP by closing and reopening its log file handles.

SIGTERM (15) — a polite termination request. The process can catch this signal, run cleanup code (flush buffers, close DB connections, save state), then exit gracefully.

kill 1234 # sends SIGTERM by default kill -15 1234 kill -TERM 1234

SIGKILL (9) — forceful, unconditional kill sent by the kernel. The process cannot catch, block, or ignore it. The OS terminates it immediately — no cleanup runs.

kill -9 1234 kill -KILL 1234

Best practice: always try SIGTERM first, wait a few seconds, then escalate:

kill -TERM 1234 sleep 5 # Only SIGKILL if process is still alive: kill -0 1234 2>/dev/null && kill -KILL 1234

SIGKILL can leave behind zombie processes, orphaned temp files, and DB corruption. Use it only as a last resort.

🔒  Permissions & Security

Use find with separate -type filters for files and directories:

find /var/www -type f -exec chmod 644 {} + # files only → 644 find /var/www -type d -exec chmod 755 {} + # directories only → 755

The + form (vs \;) batches multiple paths into a single chmod invocation — much faster on large trees.

Why not chmod -R 755? That sets 755 on both files and directories, making all files executable — a security risk for web-served files.

Also update ownership for the web server:

chown -R www-data:www-data /var/www/

The sticky bit on a directory means: only the file's owner (or root) can delete or rename that file inside the directory, even if other users have write permission on the directory itself.

Classic example — /tmp:

ls -ld /tmp # drwxrwxrwt — trailing 't' = sticky bit set # world-writable, but User A cannot delete User B's files

Setting and removing:

chmod +t /shared/uploads # symbolic chmod 1777 /shared/uploads # octal: 1 = sticky, 777 = permissions chmod -t /shared/uploads # remove sticky bit

Use cases: Shared upload directories, /tmp, multi-tenant environments where users must only manage their own files. Without it, any user with directory-write access could delete anyone else's files.

Edit sudoers safely using visudo (validates syntax before saving — a broken sudoers file can lock you out of root):

sudo visudo -f /etc/sudoers.d/deploy # use a drop-in file, never edit main sudoers

Add this line:

deploy ALL=(root) NOPASSWD: /usr/bin/systemctl restart myapp

Set correct permissions on the drop-in file:

chmod 440 /etc/sudoers.d/deploy

Key security principles:

  • Always use visudo — a syntax error can lock you out of sudo entirely
  • Use drop-in files in /etc/sudoers.d/ rather than editing the main file directly
  • Specify the full path to the command to prevent PATH hijacking
  • Never grant NOPASSWD: ALL — scope it to exactly the commands needed
  • Include specific arguments where possible to prevent abuse (e.g., can't restart an unintended service)

umask specifies which permission bits to remove from the default when new files/dirs are created.

Default permissions: files = 666, directories = 777

Files: 666 - 027 = 640 (rw-r-----) owner:rw, group:r, others: none Directories: 777 - 027 = 750 (rwxr-x---) owner:rwx, group:rx, others: none

Breaking down umask 027 by digit:

  • 0 — owner: remove nothing (full access)
  • 2 — group: remove write (group gets read-only)
  • 7 — others: remove everything (no world access)

Common umask values:

022 → files 644, dirs 755 (most common; world-readable) 027 → files 640, dirs 750 (group-readable; no world access) 077 → files 600, dirs 700 (private to owner only)

Set permanently in ~/.bashrc or /etc/profile.

🌐  Networking

Using bash's built-in /dev/tcp pseudo-device (no external tools needed):

timeout 3 bash -c '</dev/tcp/db.example.com/5432' && echo "open" || echo "closed"

Using curl (widely available):

curl -s --connect-timeout 3 telnet://db.example.com:5432; echo "Exit: $?" # exit 0 = connected (port open), exit 7 = connection refused

Using Python (almost always available):

python3 -c " import socket, sys s = socket.socket() s.settimeout(3) try: s.connect(('db.example.com', 5432)); print('open') except: print('closed'); sys.exit(1) "

The /dev/tcp bash approach is cleanest — it requires zero external tools and works in minimal containers.

Option 1 — SSH local port forwarding through a jump host:

ssh -L 15432:serverB:5432 user@serverA -N -f # Now connect: psql -h localhost -p 15432 -U myuser mydb

-L local_port:remote_host:remote_port, -N no command (tunnel only), -f background

Option 2 — SSH ProxyJump (cleaner, OpenSSH 7.3+):

ssh -J user@serverA -L 15432:localhost:5432 user@serverB -N

Option 3 — Persistent config in ~/.ssh/config (reusable shortcut):

Use curl's -w (write-out) flag with timing variables:

curl -w "\nDNS lookup: %{time_namelookup}s TCP connect: %{time_connect}s TLS handshake: %{time_appconnect}s TTFB (server): %{time_starttransfer}s Total: %{time_total}s\n" \ -o /dev/null -s https://api.example.com/endpoint
  • time_namelookup — DNS resolution
  • time_connect — TCP 3-way handshake complete
  • time_appconnect — TLS negotiation complete
  • time_starttransfer — Time To First Byte (TTFB = server processing time)
  • time_total - time_starttransfer — response body download time

For deeper network path analysis:

mtr --report api.example.com # live traceroute with packet loss per hop

ss is the modern replacement for netstat (Socket Statistics). The flags mean:

ss -tulnp
  • -t — show TCP sockets
  • -u — show UDP sockets
  • -l — show only listening sockets (server ports)
  • -n — numeric: don't resolve hostnames or port names (faster, no DNS calls)
  • -p — show the process (PID and name) owning each socket

The output shows all TCP/UDP ports currently listening, with which process owns them. Useful for:

ss -tulnp # all listening ports + owning process ss -tulnp | grep :8080 # find what's using port 8080 ss -tn state established # all active TCP connections ss -s # summary statistics

📜  Bash Scripting

This "strict mode" triplet makes scripts fail fast, surfacing bugs that would otherwise be silently ignored:

  • -e (errexit) — exit immediately if any command returns a non-zero status. Without it, scripts continue running after failures.
  • -u (nounset) — treat unset/undefined variables as errors. Prevents silent bugs from typos like $FIEL instead of $FILE.
  • -o pipefail — a pipeline returns the exit code of the first failing command. Without it, failing_cmd | tee output returns 0 because tee succeeded.
#!/usr/bin/env bash set -euo pipefail IFS=$'\n\t' # also prevents word-splitting on spaces in filenames

Gotchas: -e doesn't trigger inside if conditions or after ||. When you need a command to gracefully fail, use || true:

rm -f /tmp/work.tmp || true # explicitly allow failure count=$(grep "error" app.log || true) # grep exits 1 when no match found
#!/usr/bin/env bash set -euo pipefail THRESHOLD=85 ALERT_LOG="/var/log/disk_alert.log" df -P | awk -v t="$THRESHOLD" 'NR>1 { # strip the % from field 5 (usage) usage = substr($5, 1, length($5)-1) if (usage+0 >= t) print $6, usage"%" }' | while IFS=' ' read -r mountpoint usage; do msg="$(date +%FT%T) DISK ALERT: $mountpoint is at $usage (threshold: ${THRESHOLD}%)" echo "$msg" | tee -a "$ALERT_LOG" >&2 # Uncomment to send email: # echo "$msg" | mail -s "Disk Alert: $mountpoint" ops@company.com done

Key points:

  • df -P — POSIX format prevents line-wrapping for long mount point names
  • awk -v t="$THRESHOLD" — safely passes shell variable into awk
  • usage+0 — forces numeric comparison in awk (not string comparison)

Schedule with cron: */15 * * * * /opt/scripts/disk_check.sh

Use trap with the EXIT pseudo-signal — it runs on any exit: normal completion, set -e failure, or signal (Ctrl+C).

#!/usr/bin/env bash set -euo pipefail TMPDIR=$(mktemp -d) LOCKFILE="/var/run/myscript.lock" cleanup() { local code=$? rm -rf "$TMPDIR" rm -f "$LOCKFILE" [[ $code -ne 0 ]] && echo "FAILED (exit $code)" >&2 exit "$code" } trap cleanup EXIT # always runs on exit trap 'cleanup' INT TERM # also catch Ctrl+C and kill # Prevent parallel runs with an atomic lock (set -C; echo $$ > "$LOCKFILE") 2>/dev/null || { echo "Already running (lock: $LOCKFILE)"; exit 1 } echo "Work happening in: $TMPDIR" # ... main script logic ...

Key: a single trap cleanup EXIT is better than repeating cleanup calls at every exit point — it's impossible to forget.

Option 1 — xargs -P (simplest, no extra tools):

find . -name "*.log" -print0 | xargs -0 -P4 -I{} ./process_file.sh {} # -P4 = max 4 parallel jobs; -I{} = filename substitution

Option 2 — Background jobs with rate limiting:

MAX_JOBS=4 for file in *.log; do while (( $(jobs -r | wc -l) >= MAX_JOBS )); do wait -n 2>/dev/null || true # wait for any one job to finish (bash 4.3+) done ./process_file.sh "$file" & done wait # wait for all remaining background jobs

Option 3 — GNU parallel (most powerful):

parallel -j4 ./process_file.sh {} ::: *.log # supports retries, progress bars, job logging, remote execution

The wait -n flag (bash 4.3+) waits for the next job to finish rather than all jobs, enabling tight concurrency control. Always wait at the end to catch any final job failures.
